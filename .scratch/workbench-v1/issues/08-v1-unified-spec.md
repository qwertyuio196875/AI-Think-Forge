# ThinkForge 工作台 v1 —— 拷问驱动的阅读与创作闭环

Status: ready-for-agent

## Background / Context

- 本单综合 2026-10-19 拷问会话的全部共识，是 v1 的**唯一权威规格**；原 01–07 拆单作废（见 Comments）。
- 项目定位：运行在个人 Windows 上的 AI 阅读与内容创作工作台，把"阅读资料 → 辅助思考 → 完善想法 → 确认方案 → 生成成品"连成一条本地工作流。核心价值不在框架数量，而在这条流程可靠、可持续使用。
- 硬约束：预算 200 元阿里云百炼 token；交付目标 7 个日历天；用户每日投入 ≤2 小时（智能体为开发主力，用户只做验收与决策）；知识库当前为空（资料库尚未收集）。
- 已沉淀的领域语言与边界：术语以 GLOSSARY.md 为准；ADR-0001（拷问为规则移植）、ADR-0002（RAG 缓做）、ADR-0003（输出双轨）为本规格的硬边界。

## Problem Statement

用户手上常有一个模糊想法，现有工具把它变成可执行方案的路是断的：

- 普通聊天要么一次性生成成品文件，要么无节制地提问；既不按输入动态判断还需要什么信息，也不会在关键问题解决后主动收敛。
- 阅读与创作分离：资料总结完就停在总结，不能直接成为创作的输入；而创作又缺少"先读资料再讨论"的连续路径。
- 生成成品常见两种失败：破坏用户模板原有样式，或产出依赖服务器 / Node / 外网资源的文件，个人电脑上打不开或不可用。
- 模型接入绑死厂商、密钥易泄漏，切换成本高；任务一旦中断就从头再来。

## Solution

一个本地工作台：**拷问轮次把模糊想法收敛为经用户确认的结构化方案，资料可被准确精简地总结并流入创作，确认后经用户自己的模板生成成品（Word 与单文件 HTML 演示）**；任务状态始终持久化，模型可切换，密钥不泄漏。

拷问机制为 grilling 规则的移植适配版：每轮把当前"前沿"问题集一次问完并各附推荐答案，系统自行查事实、决策留给用户，收敛即停；未确认的推测只记为待确认事项，绝不直接变成成品。

## User Stories

**主题创作**

1. 作为用户，我想用一句话、一段描述、一份文档或一份 PPT 发起主题创作任务，让不成熟的想法也能起步。
2. 作为用户，我想系统先解析输入、识别目标 / 背景 / 约束 / 已知信息，再提出当前最有价值的问题，而不是重复询问我已提供的信息。
3. 作为用户，我想每轮把当前可决的问题一次问完、每题附推荐答案，让回答成本最低。
4. 作为用户，我想下一轮问题根据我上一轮的回答重新计算、动态调整，而不是提前列好的固定问题集。
5. 作为用户，我想系统主动指出模糊点、遗漏、矛盾、风险与未经确认的假设；我不确定时给我备选方向，帮我补齐盲区。
6. 作为用户，我想简单任务少问、复杂任务深问，关键问题解决后主动收敛，不被无限提问拖住。
7. 作为用户，我想收敛后得到结构灵活可调的结构化方案（目标、读者、核心观点、章节、执行步骤、关键约束、风险、待确认事项、输出要求等），以便审查。
8. 作为用户，我想通过继续对话修订方案，并让系统指出仍影响结果的重要未定信息，使方案在讨论中定稿。
9. 作为用户，我想未经我明确确认的推测只被记录为待确认事项，绝不直接变成成品，使责任边界清晰。
10. 作为用户，我想只有在我明确确认方案后才进入正式生成，使未获批准的内容永不被写出。

**资料分析**

11. 作为用户，我想上传 DOCX / PDF / TXT / MD / PPTX 或输入公开网页 URL 发起分析，使多来源阅读收敛到一个入口。
12. 作为用户，我想默认总结在 500 汉字内，提炼主题 / 核心观点 / 关键内容 / 重要数据 / 结论，不凑字重复、不虚构事实，使总结可信。
13. 作为用户，我想长文档被分块分析后再综合，不因单次输入长度限制遗漏重要内容。
14. 作为用户，我想系统明确提示识别不了的内容（图表 / 图片 / 扫描件等），使"未分析"不被伪装成"已完整分析"。
15. 作为用户，我想网页抓取遵守安全策略（限定协议、拒绝本机 / 内网 / 云元数据地址、限制超时 / 大小 / 重定向、需登录或受访问控制的如实提示且不绕过），使本地网络与站点权限边界不被突破。
16. 作为用户，我想总结可查看 / 复制 / 保存、可用我的模板生成 Word，并可一键送入主题创作继续拷问，使阅读产出变成创作输入。
17. 作为用户，我想资料分析默认不进入拷问流程，使快速阅读不被流程拖慢。

**成品与模板**

18. 作为用户，我想确认后的方案生成两类成品——Word 与单文件 HTML 演示，使文档与汇报两种载体都可用。
19. 作为用户，我想成品尽可能保留我提供模板的样式、结构与版式；模板缺失 / 损坏时明确报错而非静默退回空白生成，使设计不被无声破坏。
20. 作为用户，我想每种格式都有全局默认模板、任务级临时覆盖、以及每次生成实际所用模板的记录，使管理简单且可复现。
21. 作为用户，我想 HTML 为单文件、双击经 file:// 打开，样式 / 脚本 / 所需字体内联，不依赖服务器或 Node，若含网络资源则明确声明，使之在无开发环境的机器上也可直接用。
22. 作为用户，我想生成后做基本完整性检查，使结构损坏的成品不会被交到我手上。

**模型与安全**

23. 作为用户，我想新增 / 编辑 / 删除 / 设默认模型配置（服务商、地址、密钥、模型名）、做连接测试、并在任务级切换模型，使业务不绑定特定厂商。
24. 作为用户，我想密钥不进源码 / Git / 前端，优先 Windows 凭据管理器，日志脱敏，使敏感信息不扩散。
25. 作为用户，我想在调用云端模型前被明确告知提示词与资料片段可能发送给所配置的服务商，使"本地运行"不被误解为"数据不出机"。

**状态与界面**

26. 作为用户，我想任务 / 对话 / 方案 / 分析 / 成品全程保存、重启后可继续，使关闭系统不等于从头再来。
27. 作为用户，我想删除操作明示影响范围、任务失败时不丢失已保存的对话与方案，使一次误操作不毁掉本地数据。
28. 作为用户，我想耗时操作显示执行状态、可安全重试的操作不重复产出无用成品，使过程可控。
29. 作为用户，我想三栏工作台给出创作 / 分析 / 历史 / 设置四个入口，并在创作页清楚看到"当前在问什么、已确定什么、还有什么未确定"，使注意力放在决策上。
30. 作为用户，我想系统只监听本机回环、文件访问限定在工作目录白名单内、上传校验类型与大小，使同网段他人无法使用、路径不能乱探。
31. 作为用户，我想用一条启动脚本把系统跑起来，使我不必了解内部结构。

## Implementation Decisions

- 拷问流程 = grilling 规则移植适配版（ADR-0001）：每轮以"前沿式"提出 1~N 个相互独立的问题并各附推荐答案；系统自查事实、决策留给用户；收敛即停；原技能为 MIT 许可，保留署名；偏离原规则处必须显式记录。
- 术语严格使用 GLOSSARY.md 词汇（主题创作 / 拷问 / 轮次 / 前沿 / 结构化方案 / 方案确认 / 待确认事项 / 资料分析 / 总结 / 成品 / 知识库 / 模板 / 单文件 HTML / 任务 / 模型配置 / 连接测试）。
- RAG 不实现（ADR-0002）：数据模型预留资料登记、文本分块、嵌入版本字段，保证 v1.1 追加检索层不重构既有路径；单份资料的"分块 → 逐块分析 → 综合"属于分析管线，不得称为 RAG。
- 输出双轨（ADR-0003）：v1 成品 = Word（文档库 + 模板机制；内置最小默认模板，用户模板可直接替换）＋ 单文件 HTML 演示（主题族取自 OpenDesign，遵守 Apache-2.0 及附属资源各自许可与署名；样式 / 脚本 / 西文字体内联，中文用系统字体回退）；文档型 HTML 长页与 PPTX 输出不做。
- 技术栈：Python 后端 + 本地 API + LangGraph 状态工作流（逐轮对话 / 状态保存 / 任务恢复）+ Vue3 / TypeScript / Vite / Element Plus 前端；SQLite 保存任务、对话、方案、模板元数据、模型配置非敏感信息、应用设置与生成记录；原始资料、模板与成品存文件系统。
- 模型统一走 OpenAI 兼容适配层，业务代码不绑定厂商；默认档位：主流程 plus、总结流程 turbo、任务级可切 max（档位为**角色标签**，`model_name` 可编辑）；**默认服务商为 DeepSeek 并作为联调对象**（2026-10-19 用户决策变更，见 `spec.md` §9），其外部接口细节于实施时确认。
- 任务级模型切换（US23）：`tasks.provider_id` 可空；`PUT /api/tasks/{id}/model` 设置或清除；拷问、方案、修订与资料分析总结按该任务的 provider 解析，未设置时沿用默认档位。删除 provider 后任务保留悬挂引用，调用时返回可读错误，需用户重新选择。
- 资料分析回看与总结 Word（US16/US26）：`GET /api/analysis/sources` 返回来源、最新文档与总结标记；历史条目 `source_id` 指向该任务最新来源；总结可用 Word 模板生成 `.docx`，记录在 `summary_deliverables`（不伪造方案、不写 `generations`）。
- HTML 全局默认主题（US20）：`settings.deck_theme_default` 保存全局默认；生成请求未显式给 `theme` 时使用它，显式主题只覆盖本次；实际主题记入 `generations.template_used=deck-theme:<id>`。
- 模板可打开但缺少所需样式（US19）：按既有决定降级为可读样式并标 `template_style_applied=false`；只有模板缺失、损坏或非 `.docx` 才报错。
- 方案确认与生成闸门（US9/US10）：存在 open 待确认事项时，服务端拒绝确认与生成；用户须先确认或驳回。该闸门是纵深防御，不因前端已提示而移除。
- 前端布局与 DeepSeek Harness 工作台同构（左侧历史导航 / 中部会话流与方案卡片 / 底部输入胶囊），用 Element Plus 标准组件实现，不做像素级复刻。
- 密钥存 Windows 凭据管理器，SQLite 只存非敏感字段；日志不含完整密钥与不必要的敏感内容。
- 安全边界：仅监听本机回环；文件访问限定工作目录白名单；上传校验扩展名与大小；URL 抓取限定协议、封禁环回 / 私网 / 链路本地 / 元数据地址、限制超时 / 大小 / 重定向；前端构建产物由后端静态托管，一条启动脚本拉起。
- 每轮对话与方案状态自动持久化，支持重启续作。
- 界面以实用清晰为主，不做企业级仪表盘。

## Testing Decisions

- 绿地现状：本仓库没有任何已存在且可执行的代码接缝；本规格确立的接缝即本项目今后的接缝标准。
- **后端自动化测试接缝 = 本地工作台 HTTP API 边界**（进程内客户端驱动，不起真实端口、不开浏览器、不联网）：创建 / 分析 / 配置 / 历史 / 生成的全部后端故事都必须只从这一个接缝进出；前端另有 Node 纯函数单测（不替代 API 接缝），UI 走手工验收。
- 接缝出口只断言三类可观察结果：① API 返回的任务 / 方案 / 总结状态；② 持久化数据——"重启续作"以重建客户端再读验证；③ 执行数据目录中的成品文件（Word 可打开且样式映射正确；HTML 无外部网络依赖可直开）。
- 外部世界只有两个 fake 注入点：模型客户端（脚本化应答，零真实花费）与 URL 抓取（假响应 + URL 安全校验器以纯函数负测：环回 / 私网 / 链路本地 / 元数据 / 非法协议必须拦）。
- 拷问收敛行为：以模拟对话验证"简单任务少轮收敛、已知信息不重复问、确认前不生成方案"。
- 每项已完成功能都要有对应测试或验收证据；前端走手工验收（对齐每日 2 小时带宽），每单以"测试输出 + 演示成品"的证据链交付。
- 不对模型输出的语义质量做自动化断言——语义质量由人看证据链验收。

## Out of Scope

RAG / 知识库检索（ADR-0002，v1.1 首位）｜.pptx 成品输出（ADR-0003，v1.1）｜文档型 HTML 长页｜方案直接编辑按钮（仅保留对话式修订）｜OCR / 扫描件识别｜exe 打包｜模板市场与联网搜模板｜局域网 / 公网暴露与多用户｜HTML→视频渲染｜MySQL / Redis / 微服务分布式架构｜跨文档检索与向量索引（随 RAG 连体）｜dsh UI 像素级复刻（已降级为布局同构）｜模板版本市场化管理（仅记录所用模板）。

## Further Considerations

- 百炼的兼容端点、档位模型 ID 与定价、嵌入默认：实施前需按事实确认（外部调研尚未覆盖）。
- OpenDesign 单文件演示主题的具体选型与适配量、内联字体所需保留的署名清单。
- PDF / PPTX 解析库的具体选型。
- 方案结构随任务类型的裁剪与生成映射方式（不要求所有任务同一结构）。
- v1.1 是否引入本地嵌入 / 本地模型（首版不要求完全离线）。
- Word 对复杂模板结构的样式映射深度（标题级别 / 页眉页脚 / 页面布局的保留边界）遵循 ADR-0003 的"不承诺无损"口径。
- 本单吸收原 01–07 拆单后，后续执行粒度按曳光弹工单另行拆分。
