# 0002. 首版不做 RAG，schema 预留，v1.1 第一优先补齐

> **本决策已被 [ADR-0005](0005-adopt-minimal-rag.md) 取代**：「首版不实现 RAG」的结论作废，RAG 最小版已进入本次范围。「schema 预留」的做法继续有效，且正是 ADR-0005 复用 `embeddings` / `document_chunks` 的基础。以下内容保留为历史记录，勿单独援引。

- 状态：已被 ADR-0005 取代
- 日期：2026-10-19

## 背景

两份需求文档直接冲突：原文档写"首版不强制引入 RAG，将来跨文档检索时再考虑"；补充修订写"**必须**引入 RAG，不能再作为未来可选项"。

本次核实的事实：
- 用户当前**没有任何已入库资料**（资料库尚未收集），知识库为空；
- 硬期限约 **7 天**，预算 200 元（阿里云百炼额度）；
- 需求中"长文档不遗漏"靠分块逐块分析再综合即可满足，那是总结管线，不是 RAG；
- "刚上传的单份资料直接解析分析"是补充文档自己认可的形态。

在空知识库上实现 RAG，等于用 7 天中约 1~1.5 天换取当前零收益的功能。

## 决策

首版不实现 RAG。同时：
- 数据库 schema 预留资料入库记录、文本分块、嵌入版本字段，保证 v1.1 追加索引层不重构既有数据路径；
- RAG 最小版（显式添加资料 → 本地索引 → top-k 检索 → 文件名/段落级引用展示）列为 v1.1 第一优先级；
- 届时嵌入采用百炼 `text-embedding-v4`（与对话模型同服务商、OpenAI 兼容），嵌入接口保持可插拔。

## 后果

- 本决策**推翻了补充文档的"必须"条款**——这正是需要 ADR 留痕的原因，后来者勿以原文档或修订文档单独为准。
- 更换嵌入模型意味着全库重建索引，版本字段自首日即生效。
- 首版演示与验收不包含跨文档检索；不得把 map-reduce 总结宣称为 RAG。
